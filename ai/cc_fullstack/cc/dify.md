# Dify 核心功能模块梳理

> Dify（[dify.ai](https://dify.ai)）是一个开源的 LLM 应用开发平台，融合了 BaaS（后端即服务）与 LLMOps 理念，通过可视化界面整合 AI 工作流、RAG 管道、智能体能力、模型管理等，让团队从原型快速走向生产。截至 2025 年，GitHub 已获 54,000+ Stars。

---

## 一、应用类型（4+1 种开箱即用的应用形态）

| 模块 | 说明 |
|------|------|
| **聊天助手** | 对话式 AI 助手，支持多轮对话、上下文记忆，适合客服、问答等场景 |
| **文本生成** | 单次输入→输出的生成式应用，适合翻译、摘要、文案撰写等非对话场景 |
| **Agent 智能体** | 具备自主推理能力的 AI 代理，可调用外部工具、执行多步任务计划 |
| **工作流 (Workflow)** | 面向批处理/自动化的可编排流程，适合数据分析、邮件自动化等单轮确定性任务 |
| **对话流 (Chatflow)** | 工作流 + 多轮对话的结合体，适合复杂对话场景如导购、深度搜索 |

---

## 二、可视化编排引擎

| 模块 | 说明 |
|------|------|
| **拖拽式画布** | 提供 20+ 节点类型（LLM 调用、条件分支、HTTP 请求、代码执行等），零代码串起业务逻辑 |
| **图执行引擎 (v1.9)** | 基于队列的任务调度引擎，支持暂停/恢复/终止命令、WorkerPool 自动扩缩容、多节点流式输出协调 |
| **代码节点** | 在流程中嵌入 Python/Node.js 脚本，处理复杂逻辑或数据转换 |
| **Jinja 模板** | 支持 Jinja2 模板语法进行变量注入和输出格式化 |
| **条件分支与循环** | 支持 if/else 分支路由和迭代器/循环节点，实现复杂流程控制 |

---

## 三、知识库 & RAG 管道

| 模块 | 说明 |
|------|------|
| **文档解析管道** | 可视化编排从文档摄取→分块→索引→检索的全流程，支持 PDF/PPT/Word/Notion 等 20+ 格式 |
| **混合检索** | 向量检索 + 关键词/BM25 混合检索，可配置 Top-K 和 Reranker 重排序，显著提升召回精度 |
| **分块策略** | 通用分块、父子分块、Q&A 处理器等多种模式，适配不同文档密度和查询场景 |
| **图片提取与检索** | 从文档中提取图片，支持图文混合输出，适合技术手册、图表问询等场景 |
| **多元数据源** | 本地文件、在线文档、云盘（Notion/飞书）、网页爬虫，通过插件框架统一接入 |
| **向量数据库** | 支持 pgvector（默认）、Milvus、TiDB、Couchbase 等多种向量存储后端 |

---

## 四、智能体 (Agent) 与工具生态

| 模块 | 说明 |
|------|------|
| **Agent 推理引擎** | 支持 ReAct 和 Function Calling 两种推理范式，智能体可自主规划、调用工具、多步推理 |
| **内置工具** | 50+ 开箱即用工具，包括代码解释器、网页抓取、Google Search、DALL·E 绘图、WolframAlpha 等 |
| **插件市场** | 独立插件运行时（dify-plugin-daemon），市场 200+ 插件，支持自定义工具和模型接入 |
| **MCP 协议兼容** | 兼容 Model Context Protocol，可与外部 MCP Server 对接扩展能力 |
| **OpenAPI/Swagger 接入** | 通过 OpenAPI 规范一键将外部 API 注册为可用工具 |

---

## 五、Prompt IDE（提示词工程）

| 模块 | 说明 |
|------|------|
| **可视化编辑器** | 专用提示词编辑界面，支持模板变量、版本控制、多模型效果对比 |
| **变量注入** | 与工作流输入/知识库结果联动，动态组装提示词 |
| **A/B 测试** | 同一应用支持多份提示词方案并行测试，对比输出质量 |

---

## 六、模型网关

| 模块 | 说明 |
|------|------|
| **多模型统一接入** | 200+ 模型兼容（OpenAI、Claude、Gemini、DeepSeek、通义千问、Llama 等），统一 API 抽象层 |
| **OpenAI 兼容接口** | 任何兼容 OpenAI API 的模型均可直接接入，零改代码 |
| **私有化模型** | 支持接入自部署的开源模型，满足数据不出域需求 |

---

## 七、可观测性与 LLMOps

| 模块 | 说明 |
|------|------|
| **运行日志** | 记录每次调用的输入/输出、各节点执行耗时、Token 消耗，支持执行轨迹逐节点回放 |
| **性能仪表盘** | 可视化展示 Token 用量、延迟、成功率等关键指标趋势 |
| **标注与反馈** | 对生产对话进行人工标注，积累高质量训练数据，持续优化提示词 |
| **Langfuse 集成** | 原生支持 Langfuse 可观测性平台，传递 Trace/Session 标识符 |
| **异常告警** | 支持配置阈值告警，异常时主动通知运维团队 |

---

## 八、企业级特性

| 模块 | 说明 |
|------|------|
| **RBAC 权限管理** | 角色-权限-资源三级模型，精细控制团队成员的访问和操作范围 |
| **SSO 单点登录** | 支持 SAML/OIDC 等企业身份认证协议对接 |
| **数据安全** | AES-256 加密、数据脱敏、审计日志全记录 |
| **多租户隔离** | 支持工作空间级隔离，不同团队/项目的资源完全独立 |

---

## 九、发布与集成（BaaS）

| 模块 | 说明 |
|------|------|
| **一键发布** | 应用可发布为独立 Web 页面，或生成嵌入 iframe 的代码片段 |
| **REST API** | 所有功能均提供标准 RESTful API，可嵌入自有业务系统 |
| **多渠道集成** | 支持对接飞书、钉钉、企微、Slack、Discord 等即时通讯和协作平台 |

---

## 十、部署方式

| 模块 | 说明 |
|------|------|
| **Dify Cloud (SaaS)** | 免运维云端服务，含免费沙盒层，适合快速验证和中小规模使用 |
| **Docker 自托管** | 一行命令本地部署，数据完全留存，适合隐私敏感场景 |
| **Kubernetes 集群部署** | 微服务架构（api/worker/web/plugin/sandbox），支持水平扩展和高可用 |
| **AWS AMI Premium** | 单租户 VPC 部署，支持品牌定制和优先技术支持 |

## 架构总览

```
            ┌──────────────────────────────────────┐
            │            Dify 平台架构              │
            ├──────────────────────────────────────┤
            │   应用层：Chatbot | Agent | Workflow  │
            ├──────────────────────────────────────┤
            │   编排层：画布引擎 | 图执行引擎       │
            ├──────────────────────────────────────┤
            │   能力层：RAG管道 | Agent推理 | 工具  │
            ├──────────────────────────────────────┤
            │   模型层：统一网关 (200+ 模型)        │
            ├──────────────────────────────────────┤
            │   运维层：日志 | 监控 | 标注 | 告警   │
            ├──────────────────────────────────────┤
            │   底座：PostgreSQL | Redis | VectorDB │
            └──────────────────────────────────────┘
```

> **一句话总结**：Dify = 可视化工作流 + RAG 知识管道 + Agent 智能体 + 多模型网关 + 可观测运维，是 LLM 应用从原型到生产的全栈操作系统。
